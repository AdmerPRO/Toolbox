Privacy policy

Last updated: 3 October 2026. Policy version: 2026-10-03. This page explains how AdmerPRO Tools handles files and related data.

Files and processing

When you use a converter, your original file is uploaded to this server to produce the requested image or audio file. Successful jobs store both the original and the result. YouTube tools send your submitted link to YouTube through yt-dlp and store the downloaded result on this server. Failed jobs use temporary working files that are normally removed when processing ends. An abrupt shutdown can leave temporary files on disk until the operator cleans them up.

Seven-day availability and ZIP archives

Stored files remain in active storage for 7 days. Download links stop working after that period. An automated task runs at server startup and once per hour to move expired files into ZIP archives. If the server is offline or archiving fails, files remain on disk until a successful retry.

Files are grouped by UTC date in folders named DDMMYYYY. For example, 01102026 means 01.10.2026. Files from the same day share a date folder; multiple ZIP archives can be created for that day.

Archiving is not deletion. ZIP archives contain uploaded originals and generated results. Each archive is automatically deleted 30 days after it is created, rather than 30 days after the original upload. Deletion runs at startup and hourly; if the server is offline or deletion fails, the archive remains until a successful retry. This typically means about 37 days of total retention, although downtime or processing failures can extend it. The server operator can access stored files and archives. Archives are not offered for download through the website.

Download links

No account is required. Generated results have random download identifiers, but anyone with the full download link can retrieve the result during its seven-day availability. Keep your links private. Original uploads are not exposed through the download endpoint. Avoid uploading sensitive or confidential material.

Audit logs and IP addresses

For each successful upload or YouTube download, a private SQLite database stores the file UUID, type, UTC upload/job-start time, uploader IP address, original/input size, stored result size, archive status and timestamps, and total accepted download request count (request_count). The uploader IP is linked to the file in an upload index. For YouTube jobs, this is the IP of the person requesting the download; only the final downloaded result is retained and original/input size is recorded as zero because there is no browser file upload. Temporary YouTube merge and audio inputs are removed before publication.

For each file and viewer IP, we store the first and last accepted download request time and the number of requests. Requests that fail validation or refer to missing or expired files do not count. An accepted request does not prove that the transfer completed or that a person viewed the content. Shared connections, proxies, and VPNs can make an IP address an unreliable indication of identity. Original filenames, submitted YouTube URLs, and video titles are not stored in this audit database.

Security purposes and legal basis

We retain file-related IP addresses and request times to protect the website, its operator, users, and content creators against abuse, unauthorized use, and suspected unlawful uploads. These records can help investigate incidents and establish, exercise, or defend legal claims. We do not use them for advertising or tracking across websites.

Where necessary and proportionate, security and abuse-prevention processing relies on legitimate interests under Article 6(1)(f) GDPR, subject to balancing those interests against your rights and freedoms. Processing required by an applicable legal obligation relies on Article 6(1)(c). Acknowledging this policy or declaring authorship does not constitute consent to unrestricted processing or prove that processing is lawful.

You may object to processing based on legitimate interests and request access, correction, restriction, or deletion by contacting the administrator below. Requests are assessed under applicable law; deletion is not unconditional where continued retention is legally justified. We limit access to authorized persons and retain records only for the periods described in this policy.

Administrator access and prohibited content

The administrator may inspect uploaded originals, generated results, ZIP archives, and related audit records to investigate abuse, respond to reports, protect the service, and handle lawful requests from competent authorities. Do not upload illegal content or material you are not authorized to process. Audit logging does not automatically detect illegal files and does not verify a person's identity.

If we have reasonable grounds to suspect that submitted material is illegal, we may report the incident to the police or another competent authority and provide relevant files, IP records, and request times where disclosure is lawful, necessary, and proportionate. We may also respond to valid, legally binding requests. We do not automatically report every upload or publish IP addresses. An IP address alone does not reliably identify a person or establish authorship or guilt.

Audit retention and deletion

Archiving preserves file-related audit records. After the retained file and its archive copies are permanently deleted, its complete file metadata record, upload-index entry, and viewer IP rows are deleted. If an IP uploaded other retained files, the entries for those files remain. There is no separate permanent IP registry. The application does not retain a metadata row for a deleted file. Metadata left by older versions for already-deleted files is removed when the updated application starts.

Automatic cleanup runs at startup and hourly. Manual filesystem deletions are reconciled at the next successful maintenance run; downtime or failures can delay cleanup. Files predating audit logging may have incomplete metadata and no known uploader IP. Hosting logs and operator backups are separate: the operator must apply their own retention and deletion procedures to those copies.

Cookies and request information

A necessary cookie named privacy_policy stores the accepted policy version for up to one year. A new policy version requires a new acceptance. You can refuse and continue reading public pages, including this policy; media operations require acceptance. Clearing the cookie brings back the acceptance screen. This acknowledgement is not permission for unrestricted data use or illegal uploads. The cookie is unsigned and can be set manually. It is a browser preference, not verified proof of identity or reliable evidence that a person read the policy.

The home page also uses popup_seen_v2 for one day to remember dismissal of the welcome message. The application includes no advertising or analytics scripts. Rate limiting temporarily stores IP addresses and counters in memory independently of the persistent file audit records. Those counters expire and reset on restart. Server and hosting logs may include request information and errors under the operator's configuration.

External services

YouTube tools contact YouTube to retrieve video information and media. Video thumbnails load from external image hosts, which receive your connection information when your browser requests them. Image conversion, resizing, uploaded MP4 audio extraction, and video muting run on this server.
